# rtailcat

R package that embeds the Go library [tailcat](https://github.com/tailscale/tailcat) and exposes both the server and client side through R6 classes.

## Architecture

There are three layers, and each one only talks to the layer directly below it.

1. Go: `src/go/` is a tiny wrapper module whose `go.mod` pins tailcat by commit and names upstream's `cmd/libtailcat` in a `tool` directive. The package does not contain its own cgo code; it builds upstream's versioned C ABI (`tailcat.h`, ABI v1) as a static `c-archive` and links it into the package shared object.
2. Native: `src/rtailcat.cpp` (C++17, cpp11) wraps the C ABI as `rtc_*` entry points. `R/cpp11.R` and `src/cpp11.cpp` are generated by `cpp11::cpp_register()`; never edit them by hand.
3. R: `R/` holds the R6 classes `TailcatServer`, `TailcatListener`, `TailcatClient`, `TailcatConnection` and the `tailcat_*()` helper functions.

Key native-layer rules:

- The C ABI is synchronous and R is single threaded, so every blocking `tc_*` call runs on a worker thread with a cancellation token. The worker never touches R memory or the R API; results are converted to R objects on the main thread.
- Sync calls (`callback = NULL`) wait in short slices and check for user interrupts. An interrupt cancels the job and waits for the worker; if the job produced a result anyway (it completed at the same moment), the result is returned and the interrupt is dropped, because it cannot be re-raised after the call returns. Async calls deliver the result to `callback(result)` exactly once through later's event loop and return a cancel handle (class `rtc_cancel`, an external pointer holding the job's `tc_token` value and a `weak_ptr` to the job). `rtc_cancel(handle)` flags a job that is still queued and calls `tc_token_cancel`; because the worker closes the token when the job ends, token handles are never reused, and the `weak_ptr` only ever reaches its own job, a late cancel does nothing, so the handle is safe to use at any time. A job that fails validation before starting returns a handle with token 0, which does nothing.
- Connection reads, and writes plus `close_write`, each go through a per-connection FIFO lane (`Lane` in `src/rtailcat.cpp`). The main thread appends the job to the lane at submission, which fixes the order; the job's worker waits on the lane's condition variable until it is at the front, and only then calls into tailcat, so at most one tailcat call per direction is in flight while a read and a write still run concurrently. A waiting job ends without calling tailcat when it is canceled, when its deadline (taken at submission, like the token's) passes, or when its handle is closed (`rtc_close` wakes the lanes). Upstream serializes same-direction I/O only in the order threads arrive, which is why the lane exists. Each job still has its own thread.
- `timeout = 0` is a poll, for every blocking call, sync and async (owner's decision; documented as a departure from the C ABI, where a zero `timeout_ns` is an already expired token). `timeout_to_ns()` turns it into a real deadline of `poll_window_ns` (5 ms), so a poll queued in a lane waits for the job ahead of it only that long. A TCP read poll with `n > 0` (`Job::probe`, using the network code that listener and connection `Handle`s record) instead gets a token without deadline: once at the front of the lane, the worker calls `tc_conn_readable()` and either reads, which then returns at once because tailcat has the data or end of stream buffered, or reports a timeout without calling `tc_conn_read`. That keeps a poll on a readable connection from racing its own deadline (gVisor checks deadlines before readability).
- Operations in flight are capped process-wide. `operations_in_flight` (an atomic in `src/rtailcat.cpp`) counts jobs holding a worker thread, running or waiting in a lane. `submit()` checks it, after the closed, argument, and timeout checks (which never start a thread and so never count), against the `rtailcat.max_operations` option, read on the main thread at every submission through `max_operations_option()` in `R/utils.R` (default 1024, `Inf` for no cap, `NA` back to C++ when invalid). At the cap, or with an invalid option, the job ends through `finish_early()` with `TC_FAILURE` and a `rtailcat: ` message naming the option and the limit. The count is incremented just before the thread starts and decremented on thread-start failure or by the worker after it closes the token and before it publishes the result, so every path (success, error, cancel, close, interrupt) releases it and a caller who has seen a result also sees the decrement. `rtc_operations_in_flight()` exposes it for tests.
- Reads use a native buffer of at most 64 KiB (`max_read_size`) whatever `n` is, left uninitialized. `execute()` runs inside a `try`/`catch` in the worker, so no C++ exception can escape a detached thread.
- Async completions are scheduled on the later loop that was current at submission (`later::later(..., loop_id)`). Calls targeting a private loop are also kept in `private_calls()`; `sweep_private()` runs on the global loop about once a second while any are pending and delivers, on the global loop, those whose job is done and whose loop no longer exists (later drops callbacks for a destroyed loop without running them). `later::exists_loop()` is called with `list(id = id)` so the package never holds the loop object itself.
- In R, `rtc_promise()` (the one place single-step promises are created) attaches a canceler function as the `rtailcat_cancel` attribute of the promise, and `tailcat_cancel()` calls it. Multi-step reads (`read_all`, `read_exact`, `read_message`, and the read loop) are reader objects in `R/reading.R` (`start`/`want`/`feed`/`total`), run by one driver for blocking calls (`run_reader()`) and one for asynchronous calls (`start_reader()`, wrapped by `reader_promise()`); the asynchronous driver returns a canceler that cancels the step in flight and stops further steps, and the promise carries it. A new multi-step read should be a reader, not its own loop. `TailcatListener$stop_serving()` uses the same handle to cancel the serve loop's pending accept, and `TailcatConnection$stop_reading()` the read loop's canceler; in both a generation counter keeps late callbacks from an old loop from touching a new one, and a result that completed as the loop was stopped is still delivered rather than dropped.
- Addresses, private keys, and pre-shared keys reach users as `tailcat_secret` (`R/secret.R`): a classed character vector whose `print`, `format`, `str`, and `toString` methods redact. Validation (`check_string()`) strips the class with `reveal()`. No R field may hold a secret: `TailcatServer$address` calls `tc_info` each time. Before R 4.6.0 `format()` of a plain list ignores its elements' classes, so any list this package returns that holds a secret must have its own class with a `format()` method (`tailcat_keys`, and `tailcat_info` for `TailcatServer$info()`).
- Nothing about a handle is cached in R (owner's decision). Every metadata field (`$address`, `$public_key`, `$is_started`, `$port`, `$local_address`, `$remote_address`, `$network`) and `$info()` asks tailcat, or checks `$is_closed`, on each access, so after `close()` of the object or its owner they all raise `tailcat_closed`. Only `$is_closed`, `$close()`, `$format()`, `$print()`, the listener's `$server`, and the connection's `$client` and `$server` (one of them `NULL`) keep working. Each class's `$format()` builds the summary lines and `$print()` only cats them, so the two cannot drift (`format()` dispatches to `$format()` through R6's `format.R6`). Format methods must work on closed, never-started, and restored objects: they show the state and omit what cannot be fetched. A connection's `$format()` shows its local and remote endpoints (not secrets) only while it is open and `rtc_conn_write_shut()` is `FALSE`; that flag is set natively once `close_write` succeeds, because `tc_info` after both directions are shut down triggers the upstream panic below. `rtc_is_restored()` tells a handle restored from a saved session (its external pointer is NULL) from one that was closed, for the error message and the printed state.
- Tailcat failures are returned as a list with class `rtc_error` (`status`, `message`, `bytes`), not thrown; `message` is tailcat's text (possibly empty), and text the native layer makes up itself starts with `rtailcat: `. The R layer converts them to conditions with class `tailcat_<kind>` plus `tailcat_error`, where kind is `invalid_argument`, `closed`, `timeout`, `canceled`, or `failure`. Byte counts (`bytes`, and the result of a write) are integers when they fit.
- Every condition is built by `tailcat_condition()` in `R/errors.R`, from the status and the call's context (operation as a verb phrase, object kind, argument, timeout, handle); `tailcat_abort()` signals it for sync calls and `rtc_promise()` uses it for rejections, which carry no backtrace. The message is a headline per status, then tailcat's text as one `i` line (whitespace collapsed, the `invalid argument: ` prefix dropped), then any hints. It is assembled as a single preformatted string and passed to rlang without cli formatting, because cli wraps lines to the console width. Errors are attributed to the user's call: R6 methods pass their own frame (`rlang::caller_env()` from the private `check()`/`promise()` helpers), constructors pass the frame of `$new()`, and active bindings, which cannot see the expression that read them, use a conventional name such as `srv$address` (`field_call()`). R-side argument checks use `abort_invalid()`, which goes through the same builder.
- tailcat's JSON field names are converted to snake_case by `tailcat_fields()` in `R/fields.R` (explicit `field_map` for names where mechanical conversion is ugly, such as `IPv4` and `DERPPort` to `ipv4` and `relay_port`, and `derp_region_*` to `relay_region_*`); `upstream_fields()` converts a user's `region` back, accepting both styles. Server `info()` renames `local_address` to `ip`. `tailcat_build_info()$raw` keeps Go's own names.
- Where rtailcat deliberately departs from the C ABI (`timeout = 0`, `ping()` in seconds), the docs say so and link to the header through `tailcat_header_link()` in `R/abi.R`, whose `tailcat_commit` is the one place the link's commit is defined; `tools/update-tailcat.sh` rewrites it.
- Async callbacks are called through cpp11 from later's event loop and any escaping error is dropped, so R code passed as a callback must do its own `tryCatch` (build callbacks with `rtc_callback()`). R objects owned by an async job live in a main-thread-only `AsyncCall`; the worker thread never touches them.
- `src/rtailcat.cpp` uses cpp11's typed API only. Do not add raw R C API calls or macros (`SEXP`, `PROTECT`, `Rf_*`, `R_*`); if cpp11 cannot express something, raise it before reaching for the raw API.
- `later_api.h` resolves later's entry point while the shared object loads, so the `@importFrom later later` tag in `R/rtailcat-package.R` is load-bearing. It is the one deliberate exception to the no-`importFrom` rule; removing it makes the package fail to load.
- Handles are external pointers with finalizers. Child R6 objects keep a reference to their parent.

Go runtime constraints that must be preserved:

- The shared object is never unloaded (no `.onUnload` that unloads the DLL).
- Nothing works in a forked child (for example `parallel::mclapply`); entry points check the pid recorded at load.
- Addresses, private keys, and pre-shared keys are secrets. Print methods and error messages must never show them.

## Build

Requires Go (version from the `go` line of `src/go/go.mod`) in addition to the usual R toolchain.

- `configure` locates Go (`RTAILCAT_GO` as a path, which is made absolute, or a command name on PATH; otherwise PATH, then common install locations), checks its version by running `go env GOVERSION` in `src/go` (so a `GOTOOLCHAIN` that allows switching reports the toolchain the build will use), and writes `src/Makevars` from `src/Makevars.in`, escaping the substituted values for `sed`. It sets `GOTOOLCHAIN=local` unless already set and never downloads Go itself.
- Every `go` invocation of the build (`configure`, `configure.win`, both Makevars files) runs with `GOWORK=off` and `GOFLAGS` set to the module flag (`-mod=readonly` or `-mod=vendor`), so a `go.work` in a parent directory, `GOWORK`, or the user's `GOFLAGS` (environment or `go env -w`) cannot change it. The command lines still pass their own flags.
- `src/rtailcat-win.def` limits the Windows DLL's exports to `R_init_rtailcat`. The Windows build passes in CI; whether the export list is in fact limited has not been inspected.
- The Go build is a make rule in `src/Makevars.in`; outputs go to `src/go/build/`.
- Default mode uses the user's normal Go caches and downloads the pinned, checksum-verified modules. Hermetic mode (when `src/go/vendor/` exists or `RTAILCAT_HERMETIC=1`) keeps every Go cache, `HOME`, and telemetry write inside `src/go/build/`.
- `tools/vendor.sh` creates `src/go/vendor/` (32 MB, git-ignored) for offline or self-contained tarballs. Such a tarball is not for CRAN: `R CMD build` warns about file paths of more than 100 bytes in the vendored Go sources. This is accepted (owner's decision) and needs no build change.
- `tools/update-tailcat.sh <ref>` moves the tailcat pin and re-syncs `SystemRequirements` and `tailcat_commit` in `R/abi.R` (rerun `devtools::document()` afterwards so the header links in `man/` follow). It ends with a reminder to review `inst/COPYRIGHTS` when the bundled Go modules change; it does not regenerate that file.
- `NEWS.md` uses the version number in its heading (`# rtailcat 0.0.0.9000`), not "(development version)", because R's NEWS.md parser (used by `utils::news()` and `R CMD check`) skips headings without a version. `_pkgdown.yml` holds the pkgdown configuration only (no site is built); its reference index must list every documented topic that is not `@keywords internal`. It has no `url`, so `pkgdown::check_pkgdown()` stops at "url is missing" until a site URL is chosen and added there and to DESCRIPTION's `URL`.
- Minimum versions in DESCRIPTION follow the features the code uses: cpp11 0.5.4 (`cpp11::package()` stopped using the non-API `R_NamespaceRegistry`, which `R CMD check` reports in compiled code), later 1.2.0 (`later_api.h` stopped including `Rcpp.h`; private loops, loop ids, and `exists_loop()` date from 1.0.0), R6 2.1.2 (`format.R6()` calls a public `$format()`), cli 3.4.0 (`{.obj_type_friendly}`), rlang 1.0.0 (`frame_call()`). `Depends: R (>= 4.1.0)` is for the native pipe and `\(x)` lambdas in the vignette examples (`inst/examples/`); cpp11 0.5.1 and later need R 4.0.0, and any R dependency keeps `R CMD check` from noting that versioned `LinkingTo` needs R >= 3.0.2. promises, jsonlite, and the Suggests have no established minimum.
- `./cleanup` removes all build outputs, including the Go caches from a hermetic build.

CI: `.github/workflows/R-CMD-check.yaml` and `pkgdown.yaml` are the r-lib/actions templates plus an `actions/setup-go` step that reads the Go version from `src/go/go.mod` (both workflows install the package, so both need Go). `setup-r` sets `NOT_CRAN=true`, so the check runs the network tests against the local relay. The check uses `error-on: "error"` because of the one expected Go-runtime warning, which means a new warning does not fail CI; read the check log when changing compiled code or docs.

Tested platforms: macOS arm64 (development and CI), Ubuntu x86_64 on R devel, release, and oldrel-1 (CI), and Windows x86_64 with Rtools (CI). On Windows the interrupt test and the fork test are skipped, so interrupting a blocking call is untested there. macOS x86_64 is untested.

## Common commands

```sh
R CMD INSTALL .
Rscript -e 'devtools::document()'
Rscript -e 'devtools::test()'
RTAILCAT_SKIP_ONLINE=1 Rscript -e 'devtools::test()'
RTAILCAT_TEST_RELAY=public Rscript -e 'devtools::test()'
R CMD build . && R CMD check --no-manual rtailcat_*.tar.gz
```

- The end-to-end tests run a server and a client in one R process; the few that need a separate process (interrupting a blocking call, capturing the Go runtime's standard error) use `child_r()` in `tests/testthat/helper.R`, which loads the package under test (the source tree under `devtools::test()`, otherwise the installed copy) in an `Rscript` started with processx. By default they use a local relay (see below), otherwise tailcat's public relays. Every network test is gated by `skip_relay()` in `tests/testthat/helper.R`, which calls `testthat::skip_on_cran()`, then honors `RTAILCAT_SKIP_ONLINE`, fails the test at once with the relay's log path if the local relay process has exited (instead of letting each test wait out its timeout), and, only when no local relay is in use, skips if offline. Use `relay_server()` and `relay_client()` (and `relay_derp_map_url()`) in network tests so they follow the relay in use.
- `R CMD check` reports one expected warning: the Go runtime in the static archive references `stderr`, `abort`, and `exit`.
- When testing interrupt handling, note that a shell job started with `&` inherits SIGINT as ignored, so the signal never reaches R.

## Local test relay

- `tests/relay/` is a separate Go module (its own `go.mod` and `go.sum`, a `tool` directive for upstream's `internal/capitest`) pinned to the same tailcat commit as `src/go`. It is test-only, so the package's `src/go` module and vendor tree do not carry its dependencies. `tools/update-tailcat.sh` re-pins it together with `src/go`.
- `tests/testthat/setup-relay.R` runs once per test run. It decides whether to start the relay by calling `testthat::skip_on_cran()` and catching the skip (testthat does not export `on_cran()`), so it uses exactly the condition the tests use: under `R CMD check` (NOT_CRAN unset) nothing is built or started. Otherwise `start_test_relay()` in `helper-relay.R` builds capitest with `go build -mod=readonly` into a `tempfile()` directory (about 2 s with a warm Go build cache; the first build downloads modules into the normal Go module cache), makes a self-signed certificate with the `openssl` command line or, failing that, Go's `crypto/tls/generate_cert.go`, starts the relay with processx, reads the `region` from its JSON record, and sets `RTAILCAT_TEST_REGION` for the run. Teardown (`testthat::teardown_env()`) closes the relay's stdin, which makes it exit, kills it if needed, and deletes the directory. processx's `cleanup` and the stdin EOF also stop it if R dies.
- `RTAILCAT_TEST_RELAY`: `auto` (default) uses the local relay and falls back to the public relays if Go, processx, or the build is unavailable; `local` fails the run instead of falling back; `public` always uses the public relays. A non-empty `RTAILCAT_TEST_REGION` set by the user is used as is. `RTAILCAT_SKIP_ONLINE=1` skips all network tests and builds nothing. The setup prints one line saying which mode is in use and why.
- With the local relay the whole suite needs no internet access; this was checked by running it under `sandbox-exec` with all non-loopback outbound traffic denied.

## Vignette

- `vignettes/building-on-rtailcat.qmd` (Quarto, `VignetteBuilder: quarto`, so building it needs the quarto CLI; both CI workflows install it) shows three example "packages" built on rtailcat: wormhole, progress, and proxy. Every cell is `eval: false` (set in the front matter); the output is stored in the cells as `#>` lines.
- The vignette is the source of the example code. Cells labeled `<example>-def-<name>` are concatenated into `inst/examples/<example>.R` (generated; never edit them), which `tests/testthat/test-examples.R` sources. Usage cells carry `class-source: <side>` (which machine runs them; the CSS at the top of the vignette labels them), optionally `blocks: true` (the cell waits on the other side, such as a server) or `run: false` (not run, such as the Shiny app). Cells without either are not run.
- `Rscript tools/vignette.R` (needs q2r from github.com/rundel/q2r, plus Go for the relay) checks that `inst/examples/` matches the vignette and reruns every usage cell, each side in its own R process (`tools/vignette-side.R`) against the local test relay, and reports differences in the recorded output; `--update` rewrites `inst/examples/` and the cells, through q2r's tree-sitter tree so the rest of the file stays byte for byte the same. Name examples to run only those. `RTAILCAT_VIGNETTE_KEEP=<dir>` keeps each run's directory (cell code, streamed output, process logs) there for debugging. It never runs during a render or `R CMD check`.
- The run replaces addresses and public keys with placeholders (`tcAbC...xYz`, `nodekey:3f1c...9a0e`, ...) in order of first appearance within an example, and puts the real values back into code that uses a placeholder, so placeholders in the vignette's code must match that order. The examples call `TailcatServer$new()` and `TailcatClient$new()` without relay arguments; the side processes and `test-examples.R` (including its child processes) set the `rtailcat.region` and `rtailcat.derp_map_url` options to the test relay instead. The rest of the suite does not set the options globally, because tests that pass only `derp_map_url` (such as those using `silent_map_url()`) would then also get the region.
- `--update` replaces a cell's code with what actually ran, so a cell whose run stopped early loses its later lines; check the diff before committing.

## Known issues

Both issues below are upstream tailcat bugs, written up for upstream in `notes/upstream_issues.md` (git- and build-ignored). Each has a test that pins today's behavior, so it fails once the pinned tailcat commit includes a fix.

- UDP `read(n = 0)` fails with "bad buffer" (`tailcat_failure`) and drops the datagram, because of an upstream tailcat bug in the C ABI layer. `tailcat.h` does not define a zero-capacity UDP read, so upstream may fix it by making it a no-op like TCP, by truncating to zero bytes, or by rejecting the call without consuming the datagram. TODO: once fixed, update the pinning test in `tests/testthat/test-upstream-udp.R` to match (its comment gives all three cases). By the owner's decision there is no R-side workaround.
- `tc_info` on a TCP connection whose two directions have both been shut down (each side called `close_write`) panics inside tailcat with a nil pointer dereference (`internal/capi/api.go` line 483: gVisor's `RemoteAddr()`/`LocalAddr()` return nil once the endpoint leaves the connected state). libtailcat's guard recovers it, prints the panic and a goroutine stack to standard error, and returns `TC_FAILURE`. TODO: once fixed, change the pinning test at the end of `tests/testthat/test-upstream-tcp.R` (it runs the scenario in a child process to keep the stack trace out of the test output) to expect success, and consider dropping the `write_shut` check from the connection's `$format()`. No R-side workaround for `$info()` and the fields; only printing avoids it.

## Conventions

- `read_all()` and `read_all_async()` take `max_bytes` (default `Inf`): they read at most `max_bytes + 1` bytes and, if the stream is longer, raise `tailcat_failure` (status 5) with `bytes` set to the bytes read, which are discarded; the connection stays open and the rest of the stream can still be read.
- Every blocking R6 method `foo()` has a `foo_async()` twin returning a promise. Timeouts are in seconds, `Inf` means no deadline, and `0` polls.
- Choice arguments (`network`, `as`) go through `match_choice()`: the untouched default means its first value, otherwise exactly one value, with no partial matching or case folding.
- Messages (`$write_message()`, `$read_message()`, `read_loop(messages = TRUE)`) are a 4-byte unsigned big-endian length followed by the bytes; this is a documented wire format, so do not change it. rtailcat sends and accepts at most `.Machine$integer.max` bytes per message. They are TCP only (UDP datagrams are already messages).
- Secret files (`tailcat_keys_save()`, `tailcat_address_write()`) go through `write_private()` in `R/files.R`: written under `Sys.umask("077")` to a temporary file in the target folder and renamed into place, refusing to overwrite unless `overwrite = TRUE`. Readers warn (`tailcat_warning`) when the file is readable by group or others. Keys files are JSON with `private_key`, `public_key`, `preshared_key`; address files are one line.
- Relay options `rtailcat.region` (servers) and `rtailcat.derp_map_url` (servers, clients, `tailcat_address_resolve()`) are read at creation and used only when the argument is `NULL`; an explicit argument always wins. Invalid option values raise `tailcat_invalid_argument` naming the option.
- Keys: `key =` everywhere. `TailcatServer$new(key = )` takes a string or a `tailcat_keys` object (whose pre-shared key it uses unless `preshared_key` is given); `check_key()` rejects incomplete `tailcat_keys` objects. Latencies are in seconds (`ping()` divides tailcat's milliseconds by 1000).
- Changing an `rtc_*` signature requires rerunning `cpp11::cpp_register()` and updating the R6 callers together.
- Use American spelling in identifiers and docs (canceled, not cancelled), even though the upstream C ABI spells its constant `TC_CANCELLED`.
- Documentation is roxygen2 with markdown; regenerate `man/` and `NAMESPACE` with `devtools::document()` rather than editing them.
